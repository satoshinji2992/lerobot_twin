# 29 mm 彩色立方体模型实测

## 当前默认的 YOLO11n-Pose + PnP

相机实时模式用 YOLO11n-Pose 对每帧全图预测八角点，用已知边长和相机内参解算三维中心。把这个立方体投回图像后，先在轮廓内核对颜色，再尝试用可见棱边校正位姿。核验统计所预测颜色在同一色相范围内的覆盖率，以及最大连续色块的面积。三个面的亮度可以不同，红色色相在色环两端都能匹配。强观测可直接定位新方块。弱观测需要当前帧仍有相符色块，并且在前 350 ms 内能唯一匹配位置、大小、深度相近的同色目标。纯色依据不会限制画面中同一颜色的方块数量。

| 同一段实拍的统计 | 原始 YOLO-Pose | 加入纯色和时序核验 |
| --- | ---: | ---: |
| 21 个标注画面，命中 / 额外输出 | 42/42、14 个 | 42/42、0 个 |
| 19 个手持样本，命中 | 19/19 | 19/19 |
| 整段 435 帧，报出不存在的蓝块或黄块 | 205 帧 | 0 帧 |
| 整段 435 帧，红块或绿块重复报出 | 107 帧 | 10 帧 |

在第 7.8 秒，原始输出在手指上画出了多余的蓝块，背景包装也被判成黄块。核验后保留手中的绿块和桌面红块。[观看原始与核验输出的同步回放](../data/vision/model-trial/pose-purity-comparison.mp4)

这段实拍只有一红一绿两个方块。纯色门限在这段视频上开发，实拍尚缺独立场景和三维中心真值。另有 160 张合成测试图覆盖四种颜色。核验使额外三维输出从 13 个降到 1 个，匹配的真方块从 271/272 降到 263/272，其中红 59/65、绿 56/56、蓝 70/72、黄 78/79。在 16 张未摆放方块的棋盘标定照片上，两版各输出 0 个方块。

RTX 5090 本机以 60 fps 投送同一段视频，默认方案的桌面接口收到 433/435 帧，实测 59.71 fps，电脑处理 P95 为 13.0 ms，本机取帧请求至结果 P95 为 31.0 ms。这个计时从电脑发起请求开始，手机曝光、无线传输和屏幕刷新需要另行测量。

## 初次模型对照实验

在同一段 435 帧的 iPhone 手持视频上，短时调用 YOLO-Pose 补检能找回原模型在 7.8 秒漏掉的绿块。补检只接受主模型在过去 250 ms 内确认过的目标，并要求当前帧出现颜色、位置、大小和深度相符的八角点解。完全遮住方块时，补检不会延长观测。可以在[五路同步回放](../data/vision/model-trial/comparison.mp4)中对照这个片段。

| 工作台模式 | 两块均可见时命中（42 个目标） | 这 21 帧的额外输出 | 手持命中（19 次） | 电脑处理 P95 | 本机取帧请求至结果 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 现有轻量模型 | 41 | 0 | 18 | 9.3 ms | 26.3 ms |
| YOLO11n 检测框 | 41 | 39 | 17 | 9.6 ms | 26.5 ms |
| YOLO11n-Pose 八角点 + PnP | 42 | 14 | 19 | 11.6 ms | 28.3 ms |
| YOLO11n-Pose + 视觉 Transformer | 39 | 10 | 16 | 11.5 ms | 28.4 ms |
| 现有模型 + YOLO-Pose 补检 | 42 | 0 | 19 | 15.4 ms | 32.2 ms |

普通 YOLO 按二维框中心计数。其余方案按三维估计的八个角点投影中心计数。人工核对了能明确辨认红、绿两块的 21 帧，并单独核对了 19 个手持样本。匹配要求颜色正确、距人工标记中心不超过原视频的 65 像素，每个目标最多匹配一次。这个指标说明抓住了哪个目标。实拍没有独立测量的 XYZ，无法由命中率推断机械臂抓取误差。补检策略根据同一段回放的漏检设计，尚待用其他背景、蓝黄实物、机械爪和走带场景验证。

三种新网络使用相同的 384 像素输入和四种颜色，训练 20 轮。864 张训练图、128 张验证图和 160 张测试图由不同随机种子生成，使用同一张独立桌面照片作为背景来源，部分样本加入手部遮挡。实拍视频只用于评估和分析。Transformer 版本在 YOLO11n-Pose 主干末端使用 C3TR，对空间特征做多头自注意力。姿态模型预测八个角点，再用相机内参和已知边长解 PnP。

合成测试图含 272 个已知中心的方块。现有模型给出 122 个匹配的位姿，这些中心的三维误差中位数为 19.2 mm，P95 为 81.6 mm。YOLO-Pose 给出 271 个，中位数 32.0 mm，P95 为 122.0 mm。Transformer 版给出 269 个，中位数 40.9 mm，P95 为 142.7 mm。各模型成功输出的目标集合不同。合成图之间没有连续轨迹，补检模式与现有模型的结果相同。

## 在工作台试用与复测

在 `sorting_sim` 目录执行以下命令。工作台示例走相机坐标系，沿用正在使用的 IP 和端口参数即可。默认使用带纯色核验的 `pose`。对照原始 YOLO-Pose 使用 `--trial-model pose-raw`。其他试验模型为 `detect`、`vit` 和 `rescue`。

```powershell
.\twin.bat workcell --frame camera --pipeline fast --device cuda
.\.workcell-venv\Scripts\python.exe benchmark_cube_vision.py test_video.mp4 --config data/vision/workcell.json --device cuda --stream-fps 60
```

速度测试使用 RTX 5090，以每秒 60 张不同画面在本机投送这段 30 fps 视频，经过上传接口、识别、仿真渲染和桌面接口。普通检测模式只画二维框。补检模式收到 433/435 帧（59.71 fps），其余模式均收到 435/435 帧（59.99 fps）。手机曝光、Safari 编码、无线局域网和显示器刷新均在计时范围外。RTX 4060 需要用上面的回放命令单独测量。

## 重做模型对比

工作台推理使用 ONNX Runtime GPU。训练和导出另外需要 CUDA 版 PyTorch、匹配的 torchvision、Ultralytics 和 onnx。本次训练使用 torch 2.7.0+cu128、Ultralytics 8.3.228，推理使用 ONNX Runtime GPU 1.24.4。在训练环境中执行以下命令。

```powershell
python cube_model_trial.py prepare
python cube_model_trial.py detect
python cube_model_trial.py pose
python cube_model_trial.py vit
python evaluate_cube_models.py
```

在线默认权重随项目放在 `assets/cube-yolo11n-pose.onnx`。试验权重保存在 `data/vision/model-trial/runs/<模型>/weights/`，评估程序会按需从 `best.pt` 导出 `best.onnx`。若重训后要发布新权重，将已验证的 pose 导出文件复制到默认权重位置。各模型的逐帧输出与汇总分别在 `data/vision/model-trial/<模型>-replay.json` 和 `<模型>-scores.json`。


## 方块朝向验证

轻量模式用 YOLO 角点生成初值。在同色连通区域内，算法从六边形外轮廓或可分辨的四边形色面生成候选姿态，将 29 mm 模型投回原图，检查轮廓重叠和可见内部棱线。候选能改善图像拟合且深度相符时，坐标表标记“棱边校正”。轮廓缺失或色面区分不足时保留原估计。

在有本地训练背景照片的工作目录可运行 `python evaluate_cube_models.py --angle-check`。该实验使用固定的新随机种子生成 400 张图，保留遮挡和压缩，按相同颜色与投影位置关联目标，在立方体的 24 个等价旋转中取最小角误差。678 个目标中两个版本各匹配 625 个，整体中位数由 30.55° 降至 26.08°，P95 由 51.71° 降至 51.45°。触发校正的 114 个目标中位数从 31.67° 降至 4.84°。这些角度是合成数据结果，实拍视频只有位置标注。
