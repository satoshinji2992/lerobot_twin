# iPhone 29 mm 方块与机械臂三维观测台

双击 `twin.bat` 进入孪生仓控制台，点击 **视觉观测 → 连接相机**。要同时看实际运行的仓库场景，在 **开始一班** 启动演示，默认弹出可交互的 MuJoCo 窗口。选择 **网页预览** 时可在控制台右侧查看仓库。手持观察可以直接使用任一 29 mm 彩色立方体，三维位置以镜头光心为原点。固定工位模式通过红色参考块建立坐标，完成基座配准后可显示机械臂基座 XYZ。

## RTX 4060 的轻量模式

现有模型、YOLO11n、YOLO-Pose 和视觉 Transformer 的实拍结果、同步视频与短时补检启动命令见[方块模型对比](cube_model_trial.md)。

以下命令在 Windows PowerShell 的 `sorting_sim` 目录执行。GPU 运行依赖对应 CUDA 12 和 cuDNN 9，模型权重随项目提供。

```powershell
py -3.11 -m venv .workcell-venv
.\.workcell-venv\Scripts\python.exe -m pip install -r requirements-vision-gpu.txt
.\twin.bat workcell --frame camera --pipeline fast --device cuda --ip 192.168.1.20
```

将 IP 换成电脑无线网卡地址。已有工作台环境时可直接安装依赖并启动。首页「相机内参」显示保存状态、适用分辨率、标定视角数和留出图像的重投影误差。收到新画面后会核对采集配置。旧标定缺少镜头标识时，页面提示核对镜头和倍率。手机传输页也会显示工作台返回的状态。桌面选择 **手持 · 实时定位**，模型应显示 **YOLO11n-Pose + PnP**，推理设备应显示 **CUDA:0 · ONNX Runtime**。固定输入的模型优先使用 CUDA Graph，首次推理在视觉工作线程上完成图捕获。独立回放可用以下命令检验目标机器上的耗时。

```powershell
.\.workcell-venv\Scripts\python.exe benchmark_cube_vision.py test_video.mp4 --config data/vision/workcell.json --device cuda
.\.workcell-venv\Scripts\python.exe benchmark_cube_vision.py test_video.mp4 --config data/vision/workcell.json --device cuda --stream-fps 60
```

每帧由 YOLO11n-Pose 在全图预测方块颜色与八角点，随后用内参和 29 mm 边长求解 PnP。程序在三维方块投回图像的轮廓内核验色相、饱和度和连续纯色区域。手指挡住部分方块时，弱观测可通过最近 350 ms 内的同色方块位置和深度进行核对。紫色线框和半透明仿真方块表示当前帧的估计。相机坐标的 X 向右、Y 向下、Z 沿镜头向前。单色方块的对称朝向等价。选择“出结果时预测”可查看有连续观测支持的短时匀速外推，上限为 120 ms。

第一条命令测试解码和识别。第二条在独立的本机端口以指定速率投送视频中的每一帧，经过上传接口、识别、MuJoCo 渲染，统计桌面接口收到的不同帧数。手机端显示编码和上传耗时。启动时请求 60 fps，真机实测以桌面的输入帧率、预览帧率及取帧请求至结果 P95 为准。

## 手持遮挡时的线框和坐标

手持实时定位用两组匀速卡尔曼滤波器分别估计画面中的运动方向和相机深度。每帧都从同一个 29 mm 刚体位姿生成相机线框、融合坐标和 MuJoCo 方块。正常观测用紫线。手挡住方块时，颜色覆盖率、模型分数、深度突变和预期轮廓里出现的手指共同决定是否采用本帧深度。深度不可靠时用橙色实线，仍可用可见部分更新横向位置，同时保持最近可信的深度和朝向。有可信图像支持的持续远近移动可重新建立深度。

完全失检后，已连续确认的轨迹最多外推 120 ms，之后保持位置，距最后一次图像观测超过 350 ms 撤下。期间使用橙色断线。若间歇可见但深度一直不可靠，从最后一次可信深度算起最多保持 600 ms。位置表标明来源与保持时长，切换“本帧 PnP”可查看原始测量。接口的 `completions` 是本帧模型输出，`pose_tracks` 是实际绘制的刚体位姿；完全失检的轨迹没有 `measurement_index`。更换相机会话或标定会清空历史。

在手持实拍第 7.30 至 7.50 秒，绿块的原始 PnP 深度从 219 mm 跳到 281 mm，融合深度保持在约 223 mm。同一段的投影面积平方根从原始的 68.5 → 53.7 像素变为 67.6 → 66.8 像素，按工作台的半分辨率计算。数值衡量线框稳定性，实拍没有独立的深度真值。[查看遮挡片段的半速对比](../data/vision/model-trial/occlusion-depth-hold.mp4)

## 连接 iPhone 或电脑摄像头

1. 让电脑与 iPhone 接入允许设备互访的同一局域网。在 PowerShell 运行下列命令，将示例 IP 换成电脑当前 Wi-Fi 网卡的 IPv4。USB / 虚拟摄像头使用下面的另一条命令，两种模式选一种即可。
2. 在电脑打开孪生仓控制台（默认 **8765**），点击 **视觉观测 → 连接相机**，用 iPhone 相机扫弹窗中的二维码，或用 Safari 打开弹窗里的手机配置地址。手机配置默认走 **HTTP 8842**，实时相机页走 **HTTPS 8843**。手机使用弹窗中的手机配对码。桌面地址里的 `127.0.0.1` 指向电脑本机，只在电脑上打开。
3. 首次 Wi-Fi 连接时，在电脑的连接弹窗展开 **首次连接或证书尚未信任**，与 iPhone 证书详情中的值比对，再按手机配置页指引信任证书。允许相机访问，在手机相机页开始传输，保持 Safari 在前台。回到电脑，先看 **相机画面** 是否持续更新，再将待测方块放入画面。
4. 使用数据线时，先让电脑通过视频采集设备或虚拟摄像头驱动识别 iPhone，并在驱动里确认能预览画面。再在工作台点 **连接相机 → 打开电脑 USB 相机**，列出设备，选择对应的视频输入并开始传输。相同入口可以直接选普通 USB 摄像头。

```powershell
.\twin.bat workcell --ip 192.168.1.20
```

```powershell
.\twin.bat workcell --local-camera
```

手机扫码后会打开已带配对码的 HTTPS 相机页，点 **开始传输**。手机直接上传到视觉服务，孪生仓控制台从本机读取观测结果。首次使用时，可在连接弹窗展开证书设置。

如需切换到手持精测或固定参考块的工位模式，再安装 FastSAM 的依赖。精测模式首次使用时按需下载并校验权重，后续可复用缓存。

```powershell
.\.workcell-venv\Scripts\python -m pip install -r requirements-vision.txt
```

手机打不开配置页时，先核对地址是否为电脑当前的无线网 IPv4，特别是启用了 VPN 或虚拟网卡的电脑。确认防火墙对手机开放了默认 TCP 8842、8843，且 Wi-Fi 允许客户端相互访问。电脑端 8874 通过回环地址访问。仅在本机使用 USB 时，无需给手机开放端口。

在 Windows 公用 Wi-Fi 上使用默认端口时，可先启动 `workcell` 或 `vision`，再以管理员身份运行 `.\vision_firewall.ps1 -PhoneIP 手机的WiFi地址`，为指定 iPhone 放行。脚本支持用 `-WhatIf` 预览，结束后用 `-Undo` 恢复。

## 放置方块并观察 XYZ

- 将**一枚 29 mm 红色立方体**固定在工位上，在实物上标记坐标轴方向，让它的整个顶面入镜。放置绿色、蓝色或黄色目标块，目标也应为 29 mm 立方体。红色留给工位参考。参考块应固定在带面旁，与机械臂基座保持稳定的相对位置。
- 拍到清楚的顶面后，模型轮廓配合颜色、边缘及 29 mm 几何自动拟合四角，再分别求解参考块与目标的三维姿态。相机与目标在 MuJoCo 画面中随同一帧更新。XYZ 为方块中心，默认原点在红块**底面中心**，+Z 由底面指向顶面。可以把目标放到不同高度，核对 Z 的变化。
- **方块中心坐标**可以切换“本帧观测”和“融合坐标”。同色目标通过三维距离和匀速运动模型进行一对一匹配。出现歧义或单帧大幅跳变时可能暂缓输出。短时遮挡保留最后一次观测和距今时间，历史最多保留约 1.2 秒。XY 轨迹在遮挡处断开。完全失去参考时，工作台撤下实时三维坐标和仿真画面。有新相机帧时，原相机画面仍可查看。
- **定格观测**可留下当前两幅画面及坐标供对照。恢复直播后，以新帧为准。页面的重投影误差单位为像素。指定毫米精度前，用量块或独立触点在抓取区的多个 XY 位置和高度复测。
- 三维场景可切换全景、方块近景、侧面验高或俯视。用侧面看抬升，用俯视对照 XY，图上的视角名称随新渲染帧更新。工位的 X、Y、Z 轴分别用红、绿、蓝标出。

### 用量块现场验高

1. 在实时工作台展开 **现场验高**，停稳传送带，选绿色、蓝色或黄色。让所选颜色只有一个目标，核对页面显示的轨迹 ID。保持红色参考块可见。
2. 将目标放在带面，点 **采集带面基准**。页面从点击后的独立新帧读取原始 XYZ。每次至少 7 帧，首尾间隔至少 0.35 秒，且每一轴的样本极差都需在 3 mm 内。显示的 Z 中位数和极差分别描述本组中心值与波动，3 mm 是采样筛选门限。
3. 在相同 XY 放入高度已知的量块，将同一目标放在上面，静止后点 **采集第二位置**。高度差应沿当前坐标系的 Z 方向。抬起后 ID 若改变，页面会要求手动确认两次为同一实物。遮挡、超时和同色目标混入会中止本次采集。在坐标系未变化时，可保留前次基准重新采集。
4. 输入带符号的实际高度差。例如抬升 29 mm 填 `29`，降低 29 mm 填 `-29`，留在原位做重复性检查填 `0`。工作台显示两次原始 Z 中位数之差、实测减实际的误差以及两次 XY 偏移。如果 XY 偏移较大，请检查是否发生水平滑动。更换相机会话、校准配置或参考方向会清除整组记录。建议在抓取区中心和边缘分别复测。

## 用显示器测 iPhone 内参

普通**平面显示器**可以显示棋盘。相机内参对应实际使用的镜头、焦距和视频裁切。同一镜头与采集设置可以复用结果。单纯移动手机位置时，工作台会根据红块重算相机外参。尚未实测时，页面标示“使用估计内参”，使用假设的 68° 对角视场角计算深度。

1. 保持原视频持续传输，在电脑点 **棋盘标定 → 全屏 → 开始自动采集**。让完整棋盘及四周白边都进入手机画面。
2. 上下左右移动手机，变换距离，分别绕两个方向倾斜，让棋盘覆盖画面中心和四角。每个姿态稍停，查看覆盖图和清晰度反馈。程序自动提取 9 × 6 个内角，过滤模糊、低对比度和重复视角。出现条纹或反光时可调整亮度、拍摄角度，或换用平整的实体棋盘。
3. 至少采满 15 个有效视角后暂停，点 **计算并应用内参**。程序留出部分视角检验误差。验证通过后保存到默认 `data/vision/workcell.json`，当前服务随即使用，样本保存在 `data/vision/screen-calibration/`。求内参时只要求正方格的比例正确。网页棋盘无需量取实际格宽。
4. 切换镜头、变焦、分辨率、横竖向裁切，或切换到会重新裁图的 USB 驱动后，按实际送入程序的视频重新标定。工作台按采集尺寸核对保存的内参。

新版采集页还记录浏览器报告的镜头、倍率、裁切模式和采集来源。已保存的配置与本帧不匹配时，桌面保留画面并暂停三维坐标，切回原设置即可恢复。旧内参缺少这些字段时，桌面会提示核对镜头。Safari 或虚拟摄像头可能无法报告自动换镜；保持同一颗镜头、倍率和视频设置。如果浏览器不提供设备标识或清除了站点数据，重连后可能需要重新核验标定。

也可以用相同视频流保存的实体棋盘图片离线求解。例如棋盘为 9 × 6 内角、格宽 20 mm 时运行下列命令，再用 `robot-view --config workcell.json` 加载该文件。

```powershell
.\.workcell-venv\Scripts\python calibrate_workcell_camera.py board_frames --inner 9 6 --square-mm 20 --out workcell.json
```

## 建立机械臂基座坐标

1. 固定参考块与机械臂基座，记录红块实物上的 +X、+Y 方向。用已知尖端偏置的 TCP（工具中心点），依次示教红块顶面中心、沿 +X 的同高点、沿 +Y 的同高点。记录机器人控制器给出的三个**基座 XYZ，单位 mm**。方向点与中心至少相距 8 mm。
2. 打开 **基座配准**，录入三组坐标，点 **预览配准**。检查基线长度、夹角和底面中心。可启用独立第四个实物点，输入其参考坐标和用 TCP 实测的基座坐标，查看毫米误差。核对结果后保存。
3. 回到实时观测。对照已标记的实物 +X 与画面中红块顶面的 A、B、C、D，选择同方向的有向边，例如 A → B 或 B → C，再点 **确认基座方向**。坐标栏显示“机械臂基座坐标”时，XYZ 和 MuJoCo 场景采用基座坐标。纯色正方形具有四重旋转对称，重新识别后，画面角标可能相差 90°。
4. 基座配准变换可以保存。每次启动、相机重连或红色参考丢失后，系统使用参考块坐标，重新看到红块时需要再次确认方向。若机械臂基座与红块之间的位置或角度已改变，则重新示教三点。只移动手机且参考块仍然可见时，相机外参随观测更新。

在 **工位重建** 视图中，SO-101 使用静态模型姿态。在 **仓库孪生** 视图中，SO-101 跟随本班次选定的控制源。当前观测流程输出相机与方块位姿，真实关节读取、传送带 USB PWM 调速和夹爪执行需另行接入。接触、抬升和遮挡会改变目标运动，抓取结果可用抬臂后的落点或夹爪反馈另行核对。

## 帧率与延迟

三维工作台显示预览速率、取帧至今的耗时、本帧识别耗时和可用的输入帧率、识别 P95。集成入口让相机继续接收新帧，推理取最新可用画面，较慢时会跳过一部分中间帧。超过 1.5 秒的过期帧撤下实时坐标。传感器曝光、手机内部缓冲和 USB 虚拟摄像头驱动中的等待都可能增加端到端延迟。

比较 Wi-Fi 与 USB 时，保持镜头、视角、光线、分辨率一致。让相机拍摄电脑显示的毫秒计时器，将真实计时器与预览中的计时器同时截屏，多次对比时间差。对连续走带抓取，还需测量实际带速和夹爪到达时间。短时轨迹融合能减少抖动并帮助重识别；传送带速度变化和接触后的运动仍需重新观测。

## 等高平面工具的独立入口

需要固定平面上的 XY 验尺、停带锁定或验证二维预测时，单独启动 `vision`。桌面端默认 8844，手机配置与相机端默认 8842、8843。与集成 `workcell` 选用相同手机端口时，一次启动其中一个相机服务。三维观测使用独立的 `workcell` 入口。

```powershell
.\twin.bat vision --ip 192.168.1.20
# 或使用电脑已识别的视频设备
.\twin.bat vision --local-camera
```

平面工具可在 `.vision-venv` 中安装同一个 `requirements-vision.txt`。

平面工具里点“使用电脑上的 USB / 虚拟摄像头”可以改用电脑输入。切换输入后重新选四角并验尺。该工具按最近 60 张已标定画面统计请求至收图、识别和请求至结果的 P95。

### 在平面工具里选四角和验尺

桌面快速试验可直接选默认的“29 mm 方块”。固定一块参考方块并让手机尽量俯拍，点击“冻结并选四角”，按左上、右上、右下、左下点同一顶面的四个角，应用标定。第一个角为原点，旁边等高方块的中心可以有负坐标。参考块不计为待测目标，四角需持续可见；参考边缘向外最多测约 87 mm，离参考越远越需要独立验尺。需覆盖更大范围时选择“实测矩形”，按下列步骤操作。

1. 停下输送带，把手机固定在尽量正对带面的支架上。让方块在图中有清楚的顶面边缘。开始送流后保持同一镜头、方向和取景。
2. 在带面上方 **29 mm** 的平面布置四个边角清晰的固定参考点。可用相同高度的小支座放置黑白角标，围出矩形，抓取区域在矩形里面。用卡尺实测两边长度。参考点留在原处供移动检查。
3. 在电脑输入两边的毫米数，冻结画面，沿矩形依次点击原点、+X 角、对角、+Y 角。重新定位工作台或手机后再选四角。显示坐标属于这个矩形，原点与轴向由选点决定。
4. 放入彩色方块。程序用 FastSAM 分割图像，在标定平面内筛选符合 29 mm 方形几何的实例。绿色轮廓显示原始观测，绿色圆点显示该帧融合后的中心，编号在轨迹连续期间保持一致。同形、同尺寸的其它物体也可能入选。相邻物体交叉或长期遮挡后可能交换编号或分配新编号。
5. 点击“独立验尺”，在同一高度核对没参与标定的标尺。再把方块放到工作区中心和四角的已知位置，记录 XY 误差和最大误差。该版本使用局部平面换算，边缘镜头畸变须计入实测误差。验尺偏差较大时，先检查参考高度、平面、尺寸和取景。毫米是输出单位，页面显示位数不代表实际精度。

### 平面工具的停带锁定与遮挡预测

手机拿到电脑的帧序号后等待下一张视频画面，发送后等处理完成才申请下一帧。这样只保留一张在途图像。页面的帧龄从电脑签发序号开始，包含传输、推理和等待，手机传感器及系统内部成像延迟仍需用实物测量。超过 1.5 秒的结果撤下实时坐标，此阈值用于静态测量。

每个方块在顶面坐标系中维护一条匀速卡尔曼轨迹，状态为 X、Y、Vx、Vy。新画面的媒体时间决定预测步长，用一对一距离匹配关联本帧检测。连续获得足够观测后，漏检时用黄色点标出该画面时刻的预测位置，最多 350 ms，单轴模型标准差超过 5 mm 时也会停止显示。这两个数是初始阈值，需要用实际带速和误差调整。坐标只适用于方块仍在皮带上的阶段；夹爪接触、抬升或推走方块后，要另外验证抓取结果。预测点不能锁定。

停带后，同一目标至少三帧的中心在 1.5 mm 内且跨越至少 0.35 秒，才可以手动锁定。请确认皮带实际停稳；视觉阈值也可能接受很慢的滑动。锁定值记录观测时间。夹爪挡住方块后，这个值保留在历史栏。若参考点移动或遮住，则暂停整帧的毫米测量。恢复视野后重新观测方块。重连相机会清除标定和锁定值。

之后接入控制器时，可以用“停带并确认停稳 → 锁定新观测 → 下抓 → 抬臂 → 检查原位置及落点”。判断抓取成功还应结合夹爪反馈或落点图像。连续走带时需另行测量带速、成像延迟和夹爪到达时间，再按时间预测截取点。
